What is counted?

HTTP and MCP requests count once on admission. Each WebSocket or TCP open counts once. Transfer adds request and response bodies, WebSocket wire frames and TCP payloads in both directions; TLS, HTTP and relay framing are excluded. A GB is 1,000,000,000 bytes. Every endpoint and caller shares the owner's budgets.

Budgets reset on the first day of the UTC calendar month. Upgrading raises the allowance without resetting current usage. An operator may impose a lower account cap; this page and pricing reflect configured caps.

When a limit is reached

tunn stops admitting requests or transferring bytes and reports the limit reason. Streams can stop after headers have been sent. A 429 can also mean a temporary rate limit: read the reason, respect Retry-After when supplied, and check usage before retrying.

Names and transport limits

Publishing automatically attempts to reserve a name up to your plan's allowance, including random names. At the limit, additional names are temporary. Unreserved names can be claimed by another account while offline. Choose --name or --subdomain before publishing; contact support for reservation changes.

General HTTP uploads are capped at 100 MiB. Verified webhook bodies have a separate 1 MiB cap and a 10-second read deadline. Stdio MCP tool calls have a 25-second deadline; the relay forwarding deadline is 27 seconds. Return a job ID for longer work. Standalone GET/SSE on the stdio bridge is optional and returns 405; finite SSE POST responses work.
