Sharing

Share with a person

Give a verified identity access to one app, then revoke it when you are done.

1. Publish privately

tunn login
tunn http 8080 --name review-app --allow=alice@example.com

Replace the email with your recipient's verified email. Send the HTTPS URL printed by tunn. They open it and sign in using that identity; their browser should show your local app. A different, uninvited identity must be denied. No tunn installation is needed for browser visitors.

2. Change access while it runs

In another terminal, sign in as the owner. Use the actual printed endpoint name if your requested name was unavailable.

tunn share review-app bob@example.com --expires 1h
tunn access review-app
tunn unshare review-app bob@example.com

access shows current access; unshare revokes this web permission and cuts its active streams. Ask the removed user to reload: access should fail. The owner retains access. For this managed web resource, --allow seeds people on first publication. Run tunn unshare review-app alice@example.com to remove Alice too; reconnecting does not restore revoked people. Use share to add people to an existing resource.

Browser access and app authentication

tunn verifies identity before forwarding. Your app still decides what that person can do. Use --require-upstream-auth when your app must also receive its own Authorization credential. Platform credentials are stripped before forwarding.

Do not add --public to a private sharing command. Public endpoints admit anonymous requests, so removing a sharing grant does not make them private.

Keep the same URL

Request a name before publishing with --name review-app. Free automatically attempts to reserve one published name; Pro attempts up to ten. Random names also use reservation slots. A temporary, unreserved name can be taken while offline. Check name limits before relying on a URL.
