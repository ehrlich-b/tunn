OpenSSH

SSH without the tunn client

Publish a local HTTP service using the OpenSSH client already on your machine.

The relay must have its SSH front door enabled on raw TCP port 443. Verify its host-key fingerprint through a trusted operator channel before accepting it. A timeout on an HTTPS-only network can mean raw SSH is blocked.

1. Link your existing key

ssh -T -p 443 tunn.to -- login --email you@example.com

Use the email you want to publish as. Open the one-time email link within five minutes, compare the key fingerprint shown by the session, click Link SSH key, then reconnect. Opening the link alone does not enroll the key. An existing local key or ssh-agent is required; email delivery must be configured by the relay operator.

2. Publish and check

Start your local app on port 8080 and verify it on localhost. Then keep this session running:

ssh -T -p 443 -o ExitOnForwardFailure=yes \
  -R0:localhost:8080 tunn.to -- --name review-app --allow alice@example.com

Open the printed HTTPS URL as the owner, then as the invited verified email. Both should reach the app; an uninvited user should be denied. Ctrl-C or losing the SSH connection removes the tunnel. Use -T for publishing; -N does not request the command needed to publish.

Unlinked keys can publish a short-lived private endpoint with an explicit email allow-list. Their conservative limits differ from signed-in account limits; link the key for account publication. SSH webhook verification is unsupported; use the HTTP CLI verifier.

Connect to an origin SSH server

An owner with tunn installed can publish an existing SSH service, leaving the origin's login and host-key checks intact:

# Publisher: keep this running.
tunn tcp --account-only --name forge-ssh --allow alice@example.com 127.0.0.1:22
# Recipient: after linking their key to the invited email.
ssh -J tunn@tunn.to:443 deploy@forge-ssh
sftp -J tunn@tunn.to:443 deploy@forge-ssh

The recipient only needs OpenSSH. Verify both relay and origin host keys. Their key must also be authorized for the origin OS user; a tunn invite does not grant an OS login. Publishers and the SSH entry point must use the same login node; cross-node jump routing is unsupported.

Remove access

ssh -T -p 443 tunn.to -- keys list
ssh -T -p 443 tunn.to -- keys remove SHA256:YOUR_FINGERPRINT

Key removal denies new channels and closes active streams within five seconds. To remove an email from a publisher's initial allow-list, stop it and restart with the revised list.
