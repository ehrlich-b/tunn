Install and connectivity

tunn: command not found

Run export PATH="$HOME/.local/bin:$PATH", then tunn --help. Persist the PATH change in your shell profile. See install recovery if the binary is missing.

Tunnel not found or offline / Tunnel offline (503)

Keep the publisher running, use its actual printed URL and check localhost first. If reconnecting changed the name, update the URL you use. Retrying a stopped publisher will not bring it online.

Identity and access

Access denied (403)

Sign in with the invited verified email. The owner can run tunn access NAME and tunn share NAME EMAIL. Confirm the publisher's initial allow-list. A public endpoint still needs your app's own authorization if configured.

Sign in as the resource owner with tunn login:

Sharing management needs owner credentials. Run tunn login as the owner on the same relay; a publisher-only device credential cannot manage access.

Authentication required (401)

Use browser sign-in for a private app. A webhook sender cannot complete browser login: use --public with signature verification. MCP clients should use OAuth with the exact printed /mcp URL.

Usage ledger unavailable / Web permission authority unavailable (503)

Retry later. Self-hosters should check durable storage and login-node connectivity. Admission fails closed while authority is unavailable; removing authentication will not repair it.

Quotas and rates

Quota exceeded - tunnel owner's monthly limit reached (429)

Run tunn usage and check the account. All callers share the owner's monthly quota. Wait for the next UTC calendar month or use an available plan upgrade. No automatic overage payment occurs.

Bandwidth rate limit exceeded (429)

Reduce sustained transfer and retry with backoff. This per-tunnel rate ceiling is separate from the monthly allowance.

Webhook verification

webhook secret file must be private (chmod 600)

Set file mode 0600 and its directory to 0700. Use a regular file outside your repository; symlinks are rejected. Do not put the secret in command arguments.

Webhook verification failed: (401)

Read the suffix. Missing signature/timestamp headers need the configured provider's header names. Wrong signatures need the webhook signing secret and unchanged raw bytes. Timestamp errors need synchronized clocks and a fresh request. Duplicate required headers are rejected. Body-size, read-deadline and verification-capacity denials also return 401.

this provider does not sign a timestamp; custom tolerance is unsupported

Remove custom tolerance for GitHub or Shopify. Deduplicate event IDs in your app; their body signatures do not prevent replay.

Run the signed generic HMAC test and confirm an unsigned request never reaches your app.

SSH

Permission denied (publickey)

Use the intended existing key or agent. Link it to your email, compare the fingerprint and reconnect. The relay must support SSH; an origin login also requires that key to be authorized for the OS user.

REMOTE HOST IDENTIFICATION HAS CHANGED!

Stop and verify the changed relay or origin fingerprint through a trusted operator channel before updating your known-hosts entry.

SSH connects but no URL is printed

Publish with -T and a remote command, not -N. -N is for a consuming local forward. Check that the local target is running and the relay's SSH front door is enabled.

Check command flags · Read status measurements · Contact support. Include the command with secrets removed, exact message and time; never send tokens, signing files or private keys.
